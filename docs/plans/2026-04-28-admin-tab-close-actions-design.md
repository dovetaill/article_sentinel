# 管理后台标签关闭动作精简设计

## 背景

当前后台工作台标签菜单提供 `关闭当前`、`关闭其他`、`关闭左侧`、`关闭右侧`、`关闭全部` 五个动作。

实际使用中有两个问题：

1. 用户只需要保留 `关闭其他` 和 `关闭全部` 两个批量动作，其它动作属于冗余交互。
2. 现有 `关闭其他` 会保留当前激活标签和基础标签 `检测任务`，与用户预期的“只保留当前标签”不一致，因此看起来像“无效”。

## 目标

- 标签菜单只保留 `关闭其他`、`关闭全部`。
- `关闭其他` 仅保留当前激活标签，不再额外保留基础标签。
- `关闭全部` 关闭全部可关闭标签后，回到默认基础标签 `检测任务`。
- 保持现有标签会话恢复、页面现场清理和基础标签兜底逻辑不变。

## 方案对比

### 方案 A：仅隐藏多余菜单项，不改 store 语义

优点：改动最小。

缺点：`关闭其他` 仍保留基础标签，不能解决当前问题。

### 方案 B：同步调整 UI 与 store 语义（采用）

优点：交互和状态语义一致，能直接修复“关闭其他无效”的问题。

缺点：需要补充回归测试，避免后续又恢复成旧语义。

## 最终设计

### 菜单交互

右上角“标签操作”菜单只保留两项：

- `关闭其他`
- `关闭全部`

### 状态语义

- `关闭其他`：保留当前激活标签，移除其它所有可关闭标签。若当前标签就是基础标签 `/tasks`，则结果自然只剩基础标签。
- `关闭全部`：移除所有可关闭标签，并回退到基础标签 `/tasks`（标题为 `检测任务`）。

### 不变约束

- 基础标签 `/tasks` 仍不可直接关闭。
- `closeAllTabs` 之后仍必须有可见工作页，避免空工作区。
- 关闭批量标签后，已关闭标签对应的 page session 仍按现有 provider 逻辑清理。

## 影响范围

- `web/admin/src/workbench/tabs.tsx`
- `web/admin/src/workbench/store.tsx`
- `web/admin/src/workbench/tabs.test.tsx`
- `web/admin/src/workbench/store.test.ts`

## 验证要点

- 菜单只显示 `关闭其他`、`关闭全部`。
- 打开多个标签时执行 `关闭其他`，最终只剩当前激活标签。
- 执行 `关闭全部`，最终回到基础标签 `检测任务`。

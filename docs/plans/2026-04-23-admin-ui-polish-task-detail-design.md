# 管理后台第二轮视觉细修与任务详情页设计补充

## 1. 背景

第一轮重写已经完成以下基础改造：

- 替换掉原有的大横幅式后台壳层
- 新增 `文稿列表` 与 `文稿详情`
- 让 `风险结果` 进入完整稿件详情页，而不是继续依赖 `Drawer`

但当前界面仍有两类问题：

1. `关键词规则`、`检测任务`、`操作日志` 的表格密度、按钮质感和筛选条布局仍然偏 Ant Design 默认后台，不够接近 `shadcn-admin` 的纯净工作台感。
2. `检测任务` 仍然使用 `Drawer` 查看详情，和 `文稿详情` 的完整页模型不统一。

此外，当前壳层里仍残留一些无业务价值的强调文案，例如：

- 左侧 `当前环境 / 值守模式 / 统一承载规则配置、巡检执行与稿件处置流程。`
- 顶部 `政务融媒 / 值守中`

这些内容会稀释界面的纯净度与现代后台感，因此本轮一并删除。

## 2. 本轮目标

### 2.1 目标

- 对 `关键词规则`、`检测任务`、`操作日志` 做第二轮纯视觉细修
- 新增 `任务详情` 完整页 `/tasks/:taskId`
- 移除 `检测任务` 当前 `Drawer` 详情模式
- 删除所有无业务价值的“环境说明 / 值守状态 / 政务强调”文案
- 让后台更接近 `shadcn-admin` 的简洁、纯净、克制的工作台风格

### 2.2 非目标

- 不引入新的后端接口
- 不改变任务、规则、日志的业务语义
- 不新增复杂图表与统计模块
- 不增加新的一级导航

## 3. 信息架构补充

### 3.1 保持不变的一级导航

- `关键词规则`
- `检测任务`
- `风险结果`
- `操作日志`

### 3.2 新增详情路由

- `/tasks/:taskId` -> `任务详情`

### 3.3 统一后的详情模型

本轮之后，后台的深度信息统一进入完整详情页，而不是 `Drawer`：

- `风险结果 -> 文稿详情 -> 内容整改`
- `检测任务 -> 任务详情`

列表页只承担以下职责：

- 筛选
- 浏览
- 批量操作
- 跳转详情

## 4. 视觉方向补充

### 4.1 文案减法原则

只保留有业务意义的信息，不保留“气氛组文案”。

本轮明确删除：

- 左侧 `当前环境`
- 左侧 `值守模式`
- 左侧底部说明句
- 顶部 `政务融媒`
- 顶部 `值守中`

左侧只保留：

- 品牌识别
- 导航

顶部只保留：

- 页面路径
- 页面标题
- 必要操作

### 4.2 表格密度

- 表头高度压低
- 单元格上下 padding 收紧
- 操作列按钮改为轻量 text action
- hover 和边框对比降低，避免默认组件感过重

### 4.3 筛选条

- 筛选项分组排列
- 查询/重置/主操作位于右侧或同组收纳
- 输入框高度、边框、占位文案、间距统一
- 整体更像标准 admin filter bar，而不是随手摆的一排表单控件

### 4.4 卡片头

- `SectionCard` 的标题与描述进一步标准化
- 所有卡片头部高度和层级统一
- 描述更短、更克制，避免说明文字抢主内容

## 5. 页面设计补充

### 5.1 关键词规则

- 增加更规整的筛选条
- 规则表格向更紧凑的 data table 调整
- 风险与启用状态 badge 继续收敛
- `新增规则 / 编辑规则` 的 modal 表单间距、按钮样式与标题层级继续细修

### 5.2 检测任务

- 顶部 summary card 继续收紧，不再抢占主列表
- 任务表格主次层级更明确：
  - 主字段：任务编号
  - 次级字段：状态、扫描统计
  - 辅助字段：发起人、创建时间
- `查看详情` 改为跳转完整 `任务详情`
- 移除 Drawer 详情实现

### 5.3 任务详情

采用与 `文稿详情` 相同的页面结构：

1. 顶部操作区
   - 返回任务列表
   - 标题
   - 状态
   - 如有必要的主操作入口
2. 第一屏摘要卡
   - 任务编号
   - 执行状态
   - 已扫描数量
   - 命中文稿数 / 命中次数
   - 创建人
   - 创建时间
3. 中部双栏
   - 左栏：规则快照、请求范围、执行摘要
   - 右栏：当前状态说明、值守提示、快捷入口
4. 底部 tabs
   - 命中结果
   - 规则快照
   - 请求快照
   - 关联日志

### 5.4 操作日志

- 筛选区改为更标准的 filter row
- 表格更强调可跳转关系
- 文章编号跳 `文稿详情`
- 任务编号跳 `任务详情`
- 快照查看继续保留 modal，但样式更轻量

## 6. 数据与接口边界

### 6.1 任务详情复用接口

本轮不新增后端接口，直接复用：

- `GET /api/v1/article-inspect/tasks/{id}`
- `GET /api/v1/article-inspect/results?task_id=...`
- `GET /api/v1/article-inspect/logs/operations?task_id=...`

因此任务详情页采用前端组装：

- `getTaskDetail(taskId)` 取任务主信息
- `listResults({ task_id })` 取该任务命中结果
- `listOperationLogs({ task_id })` 取该任务关联日志

## 7. 技术策略

- 保持现有壳层结构不推倒重来，在其基础上做纯视觉细修
- 新增 `tasks/detail.tsx`，并将 `tasks/index.tsx` 中的 Drawer 逻辑删除
- 如有必要新增轻量 filter row / info list / task detail block 等展示组件
- 通过测试先行锁定：
  - 任务详情跳转
  - 任务详情完整页结构
  - 日志页任务/文章链接
  - 更纯净的壳层文案

## 8. 验收标准

### 8.1 视觉验收

- 左侧与顶部不再出现“当前环境 / 值守模式 / 政务融媒 / 值守中”等无效文案
- `关键词规则`、`检测任务`、`操作日志` 的筛选条、按钮、表格密度更接近 `shadcn-admin`
- 页面整体纯净度提升，说明性废话显著减少

### 8.2 交互验收

- `检测任务` 不再使用 Drawer 查看任务详情
- 存在完整任务详情页 `/tasks/:taskId`
- 日志页可跳任务详情与文稿详情

### 8.3 技术验收

- 现有接口不变
- 测试通过
- 构建通过

## 9. 结论

本轮是一次“减法 + 统一”的补充改造：

- 继续削弱无业务价值的文案装饰
- 继续压缩表格与筛选条的视觉噪音
- 将 `任务详情` 升级为完整页，从而和 `文稿详情` 彻底统一交互模型

# 管理后台标签工作台设计

## 1. 背景

当前后台右侧主工作区已经建立了 `sidebar + header + content` 的管理台结构，但导航仍然主要围绕“单页面切换”展开，存在三个明显问题：

1. 页面内仍有大量 `href` / 原生 `<a>` 跳转，导致从列表页进入详情、结果或整改页时会触发整页刷新。
2. 多个业务对象需要并行处理时，用户只能依赖浏览器返回或重复打开页面，无法像常见后台工作台一样保留多个工作现场。
3. 当前页面状态主要保存在组件本地 state 中，缺少统一的“路由状态 + 标签现场 + 刷新恢复”模型，导致切换页面后上下文容易丢失。

用户希望引入一个位于右侧主区域顶部的标签栏，使左侧导航和页内跳转都能在不刷新整个壳层的前提下打开或切换页面，并支持常见的批量关闭操作。

## 2. 目标与非目标

### 2.1 目标

- 在右侧主区域顶部增加统一标签栏，形成真正的工作台式多页签体验。
- 左侧主导航和页内跳转都通过标签系统打开页面，不再触发整页刷新。
- 列表页保持单实例，详情页、结果页、整改页支持按资源 ID 多开。
- 支持直接关闭当前标签，并在标签菜单中提供 `关闭其他`、`关闭全部` 两个批量动作。
- 保留关键工作状态，包括列表筛选条件、分页、滚动位置，以及整改页等页面的未提交现场。
- 浏览器刷新后尽量恢复当前工作台状态，并按机构隔离不同标签集合。

### 2.2 非目标

- 不重做现有业务流程、接口语义或权限模型。
- 不将后台完全改造成 IDE 式无限保活工作台。
- 不引入新的全局状态管理库，优先基于现有 React 结构扩展。
- 不在本轮扩展新的业务页面，只重构现有导航与工作区承载方式。

## 3. 方案选择

### 方案 A：轻量路由标签

做法：

- 仅在 header 下方新增标签 UI。
- 标签切换仍由当前路由重新渲染页面。
- 不额外保存页面现场状态。

优点：

- 改动最小。
- 可以较快去掉整页刷新体验。

缺点：

- 回到已打开页面时容易重新请求和重置筛选。
- 无法满足后台多任务并行处理对“工作现场保留”的核心预期。

### 方案 B：混合型工作台标签（推荐）

做法：

- 在壳层增加一个工作台标签层，统一管理打开、激活、关闭和恢复。
- 列表页尽量将筛选、分页、排序同步到 URL。
- 详情页、结果页、整改页保留关键工作状态，但不承诺完整页面实例持续保活。
- 使用 `sessionStorage` 恢复当前会话的标签集合。

优点：

- 能同时解决“无整页刷新”“多标签并行”“关键状态恢复”。
- 复杂度显著低于全量 IDE 式无限保活模型。
- 与当前 React Router + lazy routes 结构兼容度高。

缺点：

- 需要统一当前导航入口，并收口一批直接 `href` 跳转。
- 需要为列表页补一轮 URL 状态治理。

### 方案 C：全量保活工作台

做法：

- 每个打开标签对应一个长期保活页面实例。
- 任意切换都不销毁页面。

优点：

- 切换体验最好。

缺点：

- 内存占用和状态一致性风险最高。
- 资源过期、机构切换和数据污染处理明显更复杂。
- 超出当前后台的实际需求。

结论：采用方案 B。

## 4. 整体架构

### 4.1 壳层结构

后台壳层从当前的：

- `sidebar + header + active route content`

升级为：

- `sidebar + header + workbench tabs + active workbench view`

其中：

- `HeaderBar` 继续负责机构切换、用户菜单、导航折叠按钮。
- 新增 `WorkbenchTabs` 负责标签列表展示、激活、关闭和批量关闭操作。
- 新增 `workbench store` 负责标签状态、恢复逻辑、当前机构隔离及页面现场缓存。
- `AppRouteOutlet` 不再只是单纯的路由出口，而是为工作台层提供页面定义和懒加载内容。

### 4.2 路由与标签关系

- URL 仍然保留，继续作为浏览器历史和深链接的事实来源。
- 进入工作台前，先将 `/`、`/rules`、`/keywords` 等别名路径标准化为正式业务路径，再交由标签层解析。
- 标签层负责判断某个目标 URL 是：
  - 激活已有标签
  - 新建标签后激活
  - 还是回退到默认基础标签
- 浏览器刷新时，根据当前 URL 恢复激活标签；如果 `sessionStorage` 中存在同机构的标签快照，则一并恢复其它已打开标签。
- `WorkbenchProvider` 仅在机构上下文完成初始化后执行恢复，避免先按默认 org 恢复再被真实 org 覆盖。

### 4.3 页面注册表

在现有 `routes` 元数据旁增加一层工作台元信息注册表，为每类页面定义：

- 页面类型：列表页 / 详情页 / 结果页 / 整改页
- 单实例或多实例策略
- 标签 key 生成规则
- 默认标题与异步标题更新规则
- 是否允许页面现场缓存
- 默认回退页

这样可避免在壳层中散落大量 `if/else` 判断，后续新增页面也只需在注册表中声明行为。

## 5. 标签模型

### 5.1 标签类型

#### 单实例标签

以下页面只保留一个实例：

- `规则分类`
- `规则管理`
- `检测任务`
- `文稿中心`
- `操作日志`
- `新建任务`
- `风险结果`

同一路由再次打开时，不创建新标签，只激活已有标签。

#### 多实例标签

以下页面按资源 ID 多开：

- `任务详情`
- `任务结果`
- `文稿详情`
- `整改页`

示例：

- `任务#88`
- `任务#88-结果`
- `文稿#123`
- `文稿#456`

### 5.2 标签 key 规则

- 列表页直接以标准化后的路由路径作为 key，例如 `/articles`。
- 详情页与操作页使用 `页面类型 + 主键 + 子视图` 组合，例如：
  - `task:88`
  - `task:88:results`
  - `article:123`
  - `article:123:rectify`
  - `article:123:rectify:task:77:result:11`

- 列表页的 query 参数不参与 key，但会参与当前标签的 URL 状态；再次打开已存在的列表标签时：
  - 如果是侧栏或普通“回到列表”动作，则复用已有标签并保留该标签当前 query。
  - 如果是带显式 query 的工作台打开动作，则复用已有标签，但以新 query 覆盖当前 URL。
- 整改页优先使用带 `task_id`、`result_id` 的复合 key；只有缺少上下文参数时才回退到 `article:{articleId}:rectify`。

该规则保证关闭、恢复、缓存与浏览器回退时的匹配稳定，不会串页。

### 5.3 标签标题规则

- 列表页使用固定中文标题。
- 详情/结果/整改页首次打开时先显示占位标题，例如 `文稿#123`、`任务#88`。
- 页面数据加载成功后，异步更新为更易辨认的业务标题，例如 `文稿 / 春季宣传稿`、`任务结果 / inspect-20260420-01`。
- 如果加载失败，继续保留 ID 型标题，避免标签标题为空。
- 超长标题在标签中截断显示，完整内容通过 tooltip 呈现。

## 6. 导航行为

### 6.1 左侧导航

- 左侧导航点击不再直接依赖默认链接行为。
- 点击后通过工作台导航入口解析目标：
  - 已存在则激活标签
  - 不存在则新建标签并激活
- 全过程不刷新整个页面壳层。

### 6.2 页面内跳转

列表到详情、详情到整改、任务到结果等页内跳转统一改为工作台打开动作：

- 默认行为：新开目标标签并切换过去。
- 同一资源重复打开时，复用对应标签并激活。
- 需要“返回上一页”的流程记录来源标签与回退 URL；点击返回时优先激活来源标签，来源不存在时再回退到 `return_to` 指向的 URL。

这使后台真正具备“保留当前工作现场，再并行查看另一个对象”的能力。

### 6.3 浏览器前进后退

- 浏览器前进/后退仍然有效。
- 当历史记录中的 URL 对应标签已存在时，仅切换激活标签。
- 如果对应标签不存在，则按工作台规则补建标签。

## 7. 关闭与恢复规则

### 7.1 默认基础标签

工作台始终保留一个基础标签，建议使用 `检测任务`：

- 作为首次进入后台的默认工作页。
- 作为 `关闭全部` 之后的兜底页。
- 避免出现“所有标签都关闭后内容区空白”的异常状态。

对应地，后台根路径应标准化落到 `/tasks`，避免默认入口与基础标签定义不一致。

### 7.2 关闭策略

- `关闭当前`：通过标签上的关闭按钮执行；优先激活右侧相邻标签，右侧无标签时激活左侧。
- `关闭其他`：仅保留当前激活标签，其余标签全部关闭；若当前就是基础标签，则结果自然只剩基础标签。
- `关闭全部`：关闭所有可关闭标签后回到基础标签，而不是留下空工作区。

### 7.3 刷新恢复

使用 `sessionStorage` 保存：

- 当前机构下的标签列表
- 当前激活标签 key
- 标签的基础元数据（路由、标题、资源标识）
- 可安全序列化的轻量页面现场快照（如列表 query、局部 tab key），不包含大体积富文本草稿

刷新浏览器后：

1. 根据当前机构读取对应的工作台快照。
2. 以当前地址栏 URL 为优先输入，合并恢复标签集合。
3. 根据地址栏或持久化激活键恢复当前页。

仅做会话级恢复，不追求跨浏览器会话永久保留。

## 8. 状态保留策略

本轮采用“三层状态模型”：

### 8.1 URL 层

URL 负责可分享、可重建的业务状态，尤其是列表页：

- 筛选条件
- 分页参数
- 排序条件
- 局部子视图

例如文稿中心中的标题关键词、文稿 ID、页码等，应能从 query string 直接恢复。

### 8.2 Tab Session 层

标签私有现场状态负责补充 URL 不适合表达的工作上下文，例如：

- 滚动位置
- 详情页折叠/展开状态
- 局部 tabs 当前激活项
- 整改页未提交表单内容

该状态跟随标签生命周期存在，关闭标签后一起销毁。
其中：

- 详情页局部 tabs、滚动位置等轻量状态可按需快照化。
- 整改页富文本草稿本轮只保证“切换标签不丢”，默认不承诺浏览器刷新后完整恢复，避免 `sessionStorage` 体积失控。

### 8.3 会话持久化层

`sessionStorage` 负责保存标签集合与基础现场快照，用于浏览器刷新后的恢复；它不是完整 keep-alive 容器，也不承担缓存整页实例的职责。

### 8.4 保活边界

- 列表页：依赖 `URL + 标签现场状态` 恢复体验，不要求无限保活实例。
- 详情页 / 任务结果页 / 整改页：在标签存活期间优先保留关键现场，但允许通过重新挂载 + page session 恢复，而不是要求组件实例始终常驻。
- 如后续标签数量过大，可增加“最近若干页保活，其余只保留快照”的上限策略，但本轮先不引入复杂回收机制。

## 9. 数据刷新策略

- 首次打开标签：正常加载页面和数据。
- 切回已打开标签：优先从 URL 与 page session 恢复界面状态，不强制重新请求；如页面因路由切换重新挂载，也不应丢失关键工作状态。
- 用户主动点击查询、刷新或提交后，再触发明确的数据更新。
- 对列表页和结果页，可在未来补充“离开过久再回来时静默刷新”的轻度过期策略。
- 对整改页等含草稿输入的页面，不在切回时自动刷新以免覆盖未提交内容。

## 10. 机构隔离

当前后台存在 `OrgSwitcher`，因此工作台必须按机构隔离：

- 每个机构维护一套独立的标签快照。
- 切换机构后，在目标机构上下文就绪后再加载对应的标签集合。
- 如果新机构尚无快照，则只打开基础标签。
- 不做跨机构复用同一组标签，避免资源 ID 相同但上下文不同导致的数据串页。
- 主动切换机构时，以目标机构快照为优先；浏览器刷新时，以当前 URL 为优先，再补齐该机构的其余标签快照。

## 11. 异常与边界处理

### 11.1 资源失效

当详情页或整改页对应的数据不存在或已失效时：

- 保留标签壳体与标题。
- 内容区显示统一的失效/未找到提示。
- 提供 `返回列表`、`重试加载`、`关闭当前标签` 等动作。

### 11.2 路径规范化

- `/`、`/rules`、`/keywords` 等别名路径先重定向或标准化为正式业务路径。
- 工作台注册表、标签 key 与会话恢复只基于规范化后的 pathname 工作，避免同一页面出现多个逻辑标签。

### 11.3 未知路由

- 对系统无法识别的 URL，不注册为正式业务标签。
- 显示统一 404/无效页面，并提供返回基础标签的入口。

### 11.4 异步标题失败

- 页面数据请求失败时，不清空标签标题。
- 保留以资源 ID 组成的占位标题，确保用户仍可识别当前标签来源。

## 13. 测试策略

### 13.1 工作台核心测试

覆盖以下行为：

- 标签新增与复用
- 标签关闭与激活接替逻辑
- `关闭其他`、`关闭全部`
- 基础标签不会被异常清空
- 别名路径规范化与未知路由兜底逻辑
- URL 与当前激活标签始终同步

### 13.2 页面行为测试

- 左侧菜单打开列表页不触发整页刷新。
- `/tasks/new`、`/results` 等非侧栏工作页也通过标签系统打开与关闭。
- 列表页打开详情时新建标签。
- 详情页进入整改、任务页进入结果页时走统一工作台导航。
- 同一整改页在不同 `task_id` / `result_id` 上下文下不会错误复用标签。
- “返回上一页”优先回到来源标签，其次回退到 `return_to`。
- 标签切回后列表筛选、分页、滚动状态能恢复。
- 整改页未提交内容在标签切换后仍可保留。

### 13.3 机构与恢复测试

- 不同机构拥有独立标签集合。
- 浏览器刷新后能够恢复当前工作台。
- 机构初始化完成前不会错误恢复其他 org 的工作台快照。
- 资源失效、404、空态页面仍能在工作台中稳定展示。

## 14. 验收标准

- 所有主导航和页内跳转均不再触发整页刷新。
- 右侧主区域顶部存在统一标签栏。
- 列表页单实例，详情/结果/整改页支持多开。
- 标签菜单支持：`关闭其他`、`关闭全部`，并且标签本身支持直接关闭当前页。
- 切换标签后关键状态能够恢复。
- 浏览器刷新后当前工作台可恢复。
- 机构切换后标签上下文不串。

## 15. 结论

本轮优化不是单纯添加一个标签样式组件，而是将后台右侧主工作区升级为“标签工作台”：

- 由工作台层统一接管导航。
- 由 `URL + 标签现场缓存 + sessionStorage` 分层保状态。
- 由“单实例工作页 + 多实例详情页”平衡体验与复杂度。
- 由机构隔离机制避免数据上下文串页。

完成后，后台会从“单页路由切换”升级为更贴近真实运营后台的多任务工作台模型。

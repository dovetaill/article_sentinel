# 管理后台重复标头清理与文稿列表导航收口设计

## 1. 背景

当前后台已经基本完成视觉对齐，但 shell 结构仍保留了一层明显的重复页头：

1. 壳层 `topbar` 输出 `控制台 / 当前页 / 标题 / 描述`
2. 页面内部 `PageHeader` 再输出一遍标题与描述

这会导致 `关键词规则`、`检测任务`、`风险结果`、`操作日志` 等列表页顶部连续出现两套相同语义的信息，形成明显的“重复标头区”。

同时，`文稿列表` 虽然已经有独立路由与页面，但仍被放在隐藏路由中，没有出现在左侧主导航，导致用户感知上仍像“没做完”或“入口缺失”。

用户这轮要求非常明确：

- 把所有重复的顶部标头区删掉
- 去掉 `控制台 / xxx` 这类重复 breadcrumb 展示
- 不要保留冗长说明文案
- 把 `文稿列表` 直接加进左侧导航
- 保持整体继续贴近 `shadcn-admin` 默认那种冷灰、克制、弱强调的工作台节奏

## 2. 目标

### 2.1 目标

- 删除列表页顶部重复的两层标头结构
- 让 shell 回到更纯粹的 `sidebar + content` 工作台布局
- 将 `文稿列表` 提升为左侧主导航的一级入口
- 统一列表页与详情页的交互模型：列表页干净、详情页完整
- 进一步减少页面中的解释性废话，保留必要操作与信息密度

### 2.2 非目标

- 不重做业务流程
- 不调整详情页路由结构
- 不新增新的业务模块
- 不改变现有 `任务详情 / 文稿详情 / 整改页` 的完整页模式
- 不引入新的视觉品牌色

## 3. 方案选择

### 方案 A：完全移除 shell 顶部页头，列表页仅保留必要操作区（推荐）

做法：

- 删除 shell `topbar`
- 列表页不再出现 `控制台 / xxx / 描述`
- 页面内部也不再保留大号 `PageHeader + description`
- 需要主操作的列表页仅保留一行轻量工具条
- `文稿列表` 加入左侧主导航

优点：

- 最接近 `shadcn-admin` 的干净工作台感
- 一次性彻底解决重复信息问题
- 列表页、详情页职责更清晰：列表页轻、详情页完整

缺点：

- 需要同步调整多个列表页头部结构
- 需要更新一批测试断言

### 方案 B：保留 shell 顶部，但压缩为单行标题

做法：

- `topbar` 保留，只显示当前页标题
- 页面内部删除 `PageHeader`
- `文稿列表` 仍加入主导航

优点：

- 改动集中在 shell
- 页面内部可少改一些

缺点：

- 顶部仍然会保留“统一横条”存在感
- 视觉上仍不如彻底删掉更干净

### 方案 C：只删描述文案，保留 breadcrumb 与标题

做法：

- 保留 shell breadcrumb/title
- 保留页面标题
- 只清掉 description

优点：

- 改动最小

缺点：

- 无法真正解决“重复标头区”问题
- 与用户当前诉求不一致

结论：采用方案 A。

## 4. 信息架构调整

### 4.1 左侧导航

主导航调整为 5 项：

- `关键词规则`
- `检测任务`
- `风险结果`
- `文稿列表`
- `操作日志`

其中：

- `文稿详情`
- `任务详情`
- `内容整改`
- `新建检测任务`

仍然保留为非主导航的详情/操作路由，不进入左侧导航。

### 4.2 页面头部层级

统一规则如下：

- 列表页：不再使用大号描述型页头
- 详情页：保留完整页头，但去掉废话型描述
- shell：不再输出路由 breadcrumb、重复标题或描述文案

这样形成单一层级：

- 列表页直接进入工作区内容
- 详情页保留完整上下文与操作入口

## 5. 页面落地策略

### 5.1 关键词规则

- 删除大号 `PageHeader`
- 保留 `新增规则` 操作，但改成轻量页面工具条或直接放入卡片操作区
- 页面进入后尽快看到规则表格与筛选

### 5.2 检测任务

- 删除大号 `PageHeader`
- 保留 `新建任务` 按钮
- summary cards、筛选条、表格继续保留，但整体从内容区直接开始

### 5.3 风险结果

- 删除重复页头与描述
- 直接从 summary / tabs / table 工作区开始

### 5.4 操作日志

- 删除重复页头与描述
- 直接保留筛选与表格区域

### 5.5 文稿列表

- 将其提升为主导航入口
- 页面去掉冗长说明，只保留工作台需要的列表内容与跳转动作
- 视觉节奏与其它列表页统一

### 5.6 任务详情 / 文稿详情 / 内容整改

- 继续保留完整独立详情页模型
- 详情头只保留必要标题、状态与操作
- 弱化解释性描述，避免再次变回“展示型横幅”

## 6. 组件与代码影响

本轮主要涉及以下结构层：

- `web/admin/src/components/layout/topbar.tsx`
- `web/admin/src/components/layout/admin-shell.tsx`
- `web/admin/src/components/layout/sidebar-nav.tsx`
- `web/admin/src/routes.tsx`
- 各列表页中的 `PageHeader` 使用位置

核心变更方向：

1. 删除或停用 shell `topbar`
2. 调整主导航数据源，使 `文稿列表` 进入主导航
3. 简化列表页顶部结构
4. 保持详情页仍为完整页，但压掉多余描述

## 7. 测试策略

### 7.1 壳层测试

更新 `App.test.tsx`，确保：

- 不再出现 `控制台`
- 不再出现重复 breadcrumb/title/description 组合
- 左侧导航中能看到 `文稿列表`

### 7.2 页面测试

更新相关页面测试，确保：

- `关键词规则 / 检测任务 / 风险结果 / 操作日志 / 文稿列表` 不再渲染重复的大页头描述区
- 仍保留关键操作按钮与主体表格
- `任务详情 / 文稿详情` 仍能正确展示独立完整详情结构

### 7.3 回归验证

执行：

- `cd web/admin && npm test`
- `cd web/admin && npm run build`

确保结构调整没有破坏现有路由、详情跳转和列表工作区。

## 8. 验收标准

- 所有列表页顶部不再出现重复标头区
- 不再显示 `控制台 / xxx` 这类冗余 breadcrumb
- `文稿列表` 出现在左侧主导航
- 页面说明文案明显减少，整体更干净
- 详情页依然保持完整独立页结构
- 整体观感更贴近 `shadcn-admin` 的克制工作台节奏

## 9. 结论

这轮不是新功能扩展，而是一次信息架构和页面头部模型的收口：

- 删除重复页头
- 降低文案噪音
- 提升 `文稿列表` 到主导航
- 让列表页与详情页拥有更统一、更克制的交互模型

最终目标是把后台从“还有模板味的管理页”压到更接近参考站的纯工作台状态。

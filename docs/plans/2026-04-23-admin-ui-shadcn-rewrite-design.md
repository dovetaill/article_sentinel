# 管理后台 Shadcn 风格重写设计文档

## 1. 背景

当前 `web/admin` 虽然已经完成一期业务页，但整体表现仍停留在“演示型后台”阶段：

- 顶部采用大横幅式页面头，明显偏离 `shadcn-admin` 的紧凑后台布局。
- 页面骨架、卡片层级、筛选区和表格区缺少统一的 dashboard 节奏。
- `风险结果` 仍使用 `Drawer` 查看详情，缺少真正的稿件详情工作页。
- 系统中没有独立的 `文稿列表` 与 `文稿详情` 页面，导致“发现问题 -> 查看稿件 -> 进入整改”的流程不完整。

用户要求本次改造以 `https://shadcn-admin.netlify.app/` / `satnaing/shadcn-admin` 为视觉和布局参考，重写前端 UI，同时保留现有四个一级业务路由。

## 2. 目标

### 2.1 核心目标

在不改后端接口和业务能力的前提下，将 `web/admin` 重写为接近 `shadcn-admin` 的现代后台：

- 保留一级导航：`关键词规则` / `检测任务` / `风险结果` / `操作日志`
- 补充隐式业务路由：`文稿列表` / `文稿详情`
- 彻底移除当前“大表头 / 大横幅”页面头
- 统一页面布局、配色、卡片结构、筛选条、表格和详情页风格
- 打通 `风险结果 -> 文稿详情 -> 内容整改` 的完整路径

### 2.2 非目标

- 不调整后端 API 设计
- 不增加新的业务模块
- 不重做关键词、任务、结果、日志、整改的业务语义
- 不做 CMS 全量稿件中心，本次 `文稿列表` 仅承接巡检稿件视角

## 3. 信息架构

### 3.1 一级导航

保持以下四个一级导航不变：

- `关键词规则`
- `检测任务`
- `风险结果`
- `操作日志`

### 3.2 非一级导航页面

新增两个业务页，但不放入侧边栏一级导航：

- `/articles` -> `文稿列表`
- `/articles/:articleId` -> `文稿详情`

保留：

- `/articles/:articleId/rectify` -> `内容整改`

### 3.3 页面流转

- 从 `风险结果` 点击文章标题或“查看详情”进入 `文稿详情`
- 从 `操作日志` 点击文章编号进入 `文稿详情`
- 从 `文稿详情` 进入 `内容整改`
- `文稿列表` 用于以稿件视角回看巡检与处置记录

## 4. 视觉方向

### 4.1 总体原则

本次 UI 直接向 `shadcn-admin` 靠拢，但只借鉴其后台结构、层级和密度，不照搬演示内容。

视觉关键词：

- 紧凑
- 清爽
- 克制
- 数据优先
- 同一套后台系统感

### 4.2 布局结构

采用标准 dashboard 布局：

- 左侧窄边栏导航
- 顶部紧凑工具栏
- 内容区统一使用卡片、筛选条、统计卡、数据表、详情分栏

明确移除当前样式中的以下要素：

- 大横幅式页面头
- 平台介绍式三联信息卡
- 过强渐变与装饰性强调
- 每页自定义一套 header 的展示方式

### 4.3 配色与组件气质

- 主背景：浅灰白
- 卡片背景：纯白或微灰白
- 边框：轻灰线
- 主强调色：冷蓝灰
- 风险色：低饱和但语义明确
- 圆角、阴影、间距统一收敛，保持专业 SaaS 后台质感

## 5. 页面设计

### 5.1 关键词规则

- 标准页头：标题 + 主按钮 `新增规则`
- 主体为数据卡片：筛选条 + 规则表格
- 表格列围绕规则信息、风险等级、适用范围、状态、更新时间组织
- 新增/编辑使用统一 modal/sheet 样式

### 5.2 检测任务

- 顶部保留简洁统计卡，不再使用介绍型头图
- 列表强调任务编号、状态、扫描范围、命中文稿数、创建信息
- `新建任务` 改为后台标准创建页：左侧主表单，右侧说明卡

### 5.3 风险结果

- 页面结构改为筛选条 + 批量操作条 + 表格
- 列表突出文稿标题、风险等级、处置状态、命中关键词、命中次数、任务编号、更新时间
- 删除 `Drawer` 详情交互，统一跳转 `文稿详情`

### 5.4 操作日志

- 顶部为一行标准筛选条
- 下方是日志表格卡片
- 文章编号、任务编号支持跳转详情或联动筛选
- 请求快照继续保留，但以更轻量的 detail panel/modal 呈现

### 5.5 文稿列表

该页面为本次新增页面，定位为“巡检稿件列表”，不是 CMS 全站总表。

结构：

- 页头：`文稿列表`
- 顶部筛选：标题、文稿编号、状态、风险等级、任务编号、时间范围
- 主体：表格卡片

表格列建议：

- 文稿标题
- 文稿编号
- 当前状态
- 最近命中风险
- 命中次数
- 最近巡检任务
- 最近处置时间
- 操作

### 5.6 文稿详情

该页面是本次最关键的新增页面，采用完整详情页，不再使用抽屉。

结构分四层：

1. 顶部操作区：返回、标题、状态、主操作按钮
2. 摘要卡区：文稿编号、关联任务、风险等级、处置状态、命中次数、最近处理人
3. 中部双栏：
   - 左栏：原稿信息、命中片段、正文快照
   - 右栏：处置建议、当前流程、快捷动作、关联信息
4. 底部标签页：命中记录、操作记录、字段变更、关联任务

### 5.7 内容整改

- 沿用现有路由，但视觉和结构对齐新的详情体系
- 顶部提供返回文稿详情入口
- 左侧为整改表单
- 右侧为原稿对照、命中提示、提交流程提示

## 6. 数据与接口边界

### 6.1 保持不变的接口

前端继续复用现有接口：

- `GET /api/v1/article-inspect/results`
- `GET /api/v1/article-inspect/results/{id}`
- `GET /api/v1/article-inspect/logs/operations`
- `GET /api/v1/article-inspect/articles/{article_id}/operation-logs`
- `GET /api/v1/article-inspect/articles/{article_id}/change-logs`
- `GET /api/v1/article-inspect/articles/{article_id}/rectify`
- `PUT /api/v1/article-inspect/articles/{article_id}/rectify`

### 6.2 文稿列表实现边界

当前后端没有“全量 CMS 文稿列表”接口，因此本次 `文稿列表` 使用现有巡检结果数据按稿件维度聚合后展示。这样可以在不改 API 的前提下提供稿件视角工作页。

### 6.3 文稿详情实现策略

`文稿详情` 通过以下方式组装：

- 基于 `article_id` 查询结果列表，获取关联巡检结果
- 选择主结果调用结果详情接口，获取命中信息和正文快照
- 并行拉取该稿件的操作日志与字段变更
- 在前端统一组装为详情页模型

## 7. 技术策略

### 7.1 改造原则

- 保留 `src/services/*` 业务请求层
- 保留 `react-router-dom` 主体结构
- 优先替换壳层、样式 token、页面展示结构
- 通过共享 UI primitive 统一各页视觉语言

### 7.2 主要改造点

- 重写 `AdminShell / Topbar / SidebarNav`
- 新增更贴近 `shadcn-admin` 的 page header、filter bar、detail section、meta list、tabs layout
- 调整 `results` 页由抽屉详情改为完整详情跳转
- 新增 `articles/index.tsx` 与 `articles/detail.tsx`
- 更新测试，先写失败用例，再逐步完成页面重构

## 8. 验收标准

### 8.1 UI 验收

- 所有页面去除当前的大横幅式页头
- 后台整体布局、层级和密度明显向 `shadcn-admin` 靠拢
- 页面之间呈现统一系统感

### 8.2 流程验收

- 仍保留四个一级路由
- 补齐 `文稿列表` 与 `文稿详情`
- `风险结果 -> 文稿详情 -> 内容整改` 路径打通

### 8.3 技术验收

- 不改后端接口
- 现有页面业务能力不回退
- 前端测试更新并通过
- 构建通过

## 9. 结论

本次不是对现有界面“微调”，而是一次明确的前端重写：

- 保留原有业务骨架
- 把展示层彻底拉回到 `shadcn-admin` 的后台语言
- 以 `文稿列表` 和 `文稿详情` 补齐稿件工作流
- 通过统一壳层和页面结构消除当前“每页一个大表头”的问题

# 文稿中心查询交互修正设计

**目标**
- 文稿中心默认显示“已发布 + 已下线”文稿，不混入待审等其他状态。
- 标题/文稿 ID 相同条件下再次点击“查询文稿”仍然重新请求接口。
- 请求未完成时阻止重复点击查询、重置和分页，避免并发重复请求。
- 检测任务继续只扫描 `state=9` 的在线文稿，不改动巡检候选逻辑。

**方案**
- 前端文稿中心页增加一个显式的刷新触发键；查询/重置时即使筛选值未变化，也会触发重新拉取列表。
- 前端在请求进行中立刻进入 loading 态，并禁用查询、重置、分页交互；同时忽略过期响应，避免数据被旧请求回写。
- 文稿中心页面不再显式传 `state=9`；后端文章列表接口在未传 `state` 时默认过滤为 `state IN (8, 9)`，传了 `state` 时仍按精确状态查询。
- 检测任务继续沿用候选文稿仓储的 `ArticleStateOnline` 默认值，确保扫描范围不变。

**验证**
- 更新 Vitest：覆盖重复查询可重发请求、加载中阻止重复点击、文稿中心不再固定传 `state=9`。
- 更新 Go 接口测试：覆盖文章列表默认只返回 8/9 状态，仍支持标题/ID 查询。
